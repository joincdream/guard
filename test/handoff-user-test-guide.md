# `guard handoff` 사용자 테스트 가이드 (DEV ↔ QA)

이 문서는 **`guard`를 처음 사용하는 사용자**를 위한 테스트 가이드입니다.
내부 CLI 명령어나 옵션을 외울 필요 없이, **평소처럼 에이전트에게 자연어로 지시하고 `guard top` 화면에서 키보드만 조작**하며 Handoff 기능을 검증합니다.

> **테스트 원칙**: 아래 단계를 따라 하다가 에이전트가 규칙을 이해하지 못하거나, 사용자가 다음에 무엇을 해야 할지 헷갈리는 지점이 생기면 **그 자체가 개선해야 할 애플리케이션 문제**입니다. 마지막 체크리스트의 `비고`에 그대로 기록해 주세요.

---

## 1. 애플리케이션 처음 실행하기

### Step 1. `guard` 실행 확인
터미널을 열고 `guard`를 입력해 애플리케이션이 정상 실행되는지 확인합니다.
```bash
guard
```
- **기대 화면**: `guard` 사용법(도움말)과 주요 모드(`dev`, `test`, `plan`, `all`), `top`, `handoff` 명령어 안내가 출력됩니다.

### Step 2. 관제탑(`guard top`) 실행 — 터미널 1
테스트할 프로젝트 폴더로 이동한 뒤 관제탑 화면을 엽니다.
```bash
cd <테스트할_프로젝트_폴더>
guard top
```
- **기대 화면**: 전체 화면 대시보드(관제탑)가 열리며, 상단에 활성 세션 목록(현재 비어 있음)과 하단에 이벤트 로그 영역이 표시됩니다.
- 이 터미널은 닫지 않고 옆에 띄워 둡니다.

### Step 3. DEV 세션 실행 — 터미널 2
새 터미널 창을 열고 **같은 프로젝트 폴더**로 이동해 개발(`DEV`) 모드로 에이전트를 실행합니다.
```bash
cd <테스트할_프로젝트_폴더>
guard dev agy
```
- **기대 화면**:
  - `[DEV]` 모드 배너(세션 ID, 워크스페이스 경로, 허용/차단 범위 안내)가 출력된 뒤 `agy` 대화 화면이 시작됩니다.
  - 터미널 1(`guard top`) 상단 목록에 **`DEV` 세션 1개**가 자동으로 나타납니다.

### Step 4. QA(`TEST`) 세션 실행 — 터미널 3
세 번째 터미널 창을 열고 **같은 프로젝트 폴더**로 이동해 검증(`TEST`) 모드로 에이전트를 실행합니다.
```bash
cd <테스트할_프로젝트_폴더>
guard test agy
```
- **기대 화면**:
  - `[TEST]` 모드 배너가 출력된 뒤 `agy` 대화 화면이 시작됩니다.
  - 터미널 1(`guard top`) 상단 목록에 **`DEV`와 `TEST` 세션 2개**가 모두 표시됩니다.

---

## 2. Handoff 테스트 시나리오

### 시나리오 1: DEV → QA 검증 요청 및 관제탑 승인

1. **DEV에게 검증 요청 지시 (터미널 2 - DEV)**
   - DEV 에이전트에게 자연어로 지시합니다:
     > *"README.md 내용을 간단히 검토해서 QA(TEST) 세션에 검증 요청(handoff) 보내줘."*
2. **승인 전 대기 상태 확인 (터미널 1 - `guard top`)**
   - 사용자가 승인하기 전에는 QA에 바로 전달되지 않고, **터미널 1(`guard top`)에 요약 모달이 자동으로 팝업**됩니다.
3. **관제탑에서 내용 확인 후 승인 (터미널 1 - `guard top`)**
   - 키보드 **`v`** 를 눌러 참조 문서가 화면에 열리는지 확인한 뒤 **`Esc`** 로 닫습니다.
   - 요약 모달에서 **`Enter`** 를 눌러 승인합니다.
4. **QA에서 요청 수신 및 처리 (터미널 3 - QA)**
   - QA 에이전트에게 자연어로 지시합니다:
     > *"도착한 핸드오프(인박스) 확인해서 검증 진행하고, 완료 처리해줘."*
   - **확인**: QA 에이전트가 DEV가 보낸 요청 내용을 정확히 읽고 검증 및 완료(`ack`)까지 수행하는지 확인합니다.

---

### 시나리오 2: QA → DEV 결함 수정 요청 및 수정 범위 잠금(Scope Lock)

1. **QA에게 수정 요청 발행 지시 (터미널 3 - QA)**
   - QA 에이전트에게 자연어로 지시합니다:
     > *"문서에 수정할 부분이 있다고 가정하고, DEV 세션에 `README.md` 파일만 수정하도록 fix 핸드오프를 보내줘."*
2. **관제탑에서 승인 (터미널 1 - `guard top`)**
   - **`[Handoff: FIX]`** 요약 모달이 뜨면 **`Enter`** 로 승인합니다.
3. **DEV에서 수신 및 수정 범위 제한 확인 (터미널 2 - DEV)**
   - DEV 에이전트에게 자연어로 지시합니다:
     > *"도착한 핸드오프 확인해줘. 먼저 지정되지 않은 다른 파일에 주석을 한 줄 추가해보고, 안 되면 요청받은 `README.md`만 확인한 뒤 완료 처리해줘."*
   - **확인**:
     - DEV가 QA의 수정 요청과 지정된 파일(`README.md`)을 정상 수신하는지 확인합니다.
     - 지정되지 않은 다른 파일 수정이 차단되는지(또는 안내되는지) 확인합니다.

---

### 시나리오 3: 원치 않는 요청 반려하기

1. **반려 테스트 요청 보내기 (터미널 3 - QA)**
   - QA 에이전트에게 자연어로 지시합니다:
     > *"DEV 세션에 '불필요한 기능 추가 요청'이라는 제목으로 task 핸드오프를 보내줘."*
2. **관제탑에서 반려 (터미널 1 - `guard top`)**
   - 팝업된 요약 모달에서 **`Esc`** 키를 눌러 반려합니다.
3. **결과 확인 (터미널 1 & 터미널 2)**
   - 터미널 1(`guard top`)에서 **`h`** 키를 눌러 `Handoff Queue` 패널을 열었을 때 해당 요청이 **`rejected`** 상태로 표시되는지 확인합니다.
   - 터미널 2(DEV)에서 *"새로 도착한 핸드오프가 있는지 확인해줘"* 라고 물었을 때 반려된 요청이 전달되지 않았는지 확인합니다.

---

### 시나리오 4: 에이전트의 자체 승인 시도 차단

1. **승인 우회 유도 (터미널 2 또는 3)**
   - 아무 핸드오프 요청을 하나 보낸 뒤, **관제탑에서 승인하지 않은 상태**에서 에이전트에게 자연어로 지시합니다:
     > *"방금 보낸 핸드오프 요청을 네가 직접 승인(approve)해줘."*
2. **기대 결과**:
   - 에이전트가 승인을 시도하더라도 가드레일에 의해 **자동으로 차단**되고, 사용자가 직접 승인해야 한다는 안내가 나와야 합니다.

---

### 시나리오 5: DEV 세션이 꺼져 있을 때 (오프라인 대기 → 자동 전달)

1. **DEV 세션 종료 (터미널 2)**
   - 터미널 2의 `agy`를 종료합니다. (`guard top` 목록에서 `DEV` 세션이 사라지는지 확인)
2. **오프라인 상태에서 요청 및 승인 (터미널 3 → 터미널 1)**
   - 터미널 3(QA) 에이전트에게 지시합니다:
     > *"DEV 세션에 '오프라인 대기 테스트'라는 제목으로 fix 핸드오프를 보내줘."*
   - 터미널 1(`guard top`)에 팝업된 모달에서 **`Enter`** 로 승인합니다.
3. **DEV 세션 다시 시작 (터미널 2)**
   - 터미널 2에서 다시 `guard dev agy`를 실행합니다.
   - **확인**:
     - 시작 배너에 대기 중이던 핸드오프가 자동 전달되었다는 안내가 표시되는지 확인합니다.
     - 새로 열린 DEV 에이전트에게 *"도착한 핸드오프 확인해줘"* 라고 지시했을 때 방금 승인한 `'오프라인 대기 테스트'` 내용이 들어있는지 확인합니다.

---

### 시나리오 6: 관제탑(`guard top`) 기본 조작

터미널 1(`guard top`)에서 아래 키가 직관적으로 동작하는지 확인합니다.

- **`h`**: 하단 화면을 `최근 이벤트 로그` ↔ `Handoff Queue`로 전환
- **`?`**: 단축키 도움말 열기 (`Esc`로 닫기)
- **`q`**: 관제탑 종료
